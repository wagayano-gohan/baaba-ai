# コンシェルジュUI(v2)実装プロセス記録（統合報告担当への引き継ぎ資料）

## 0. 背景・退避作業
- 旧UI（v1、予定管理アプリ寄りで不採用）はGitで退避済み。
  - `git init`後、v1一式を`master`ブランチにコミット（コミット`2e2ab4f`）
  - `archive/ui-prototype-v1-rejected`ブランチを作成し、このコミットを恒久的に参照可能な状態で保持（今後更新しない）
  - 新規作業ブランチ`feature/concierge-ui`を作成・チェックアウトし、以降の新UI実装はすべてこのブランチ上で実施
  - コードは削除しておらず、`git checkout archive/ui-prototype-v1-rejected`でいつでも旧UIを参照可能
  - TIMBLE OS等の他プロジェクト・他の開発サーバーへの影響は確認済みでなし

## 1. product-requirements：新要件定義
成果物：`docs/concierge-requirements.md`
- 不採用理由（v1）の整理、体験コンセプト「ばーば専属の生活コンシェルジュ」の定義
- 最重要原則10項目（音声主役、ホームは最小要素、考えさせない等）
- 5画面（A.コンシェルジュホーム／B.聞き取り中／C.AI確認／D.完了／E.予定確認）の要件

## 2. senior-ux：画面構成設計（複数回の差し戻しを経て確定）
成果物：`docs/concierge-screen-design.md`
- 初版作成後、product-reviewer・qa-accessibilityの事前レビューで計4回の差し戻しサイクルを経て確定
- 主な修正内容：
  - E-2の「変更する」「けす」同時常設ボタンを解消し、「変更する」を唯一の常設操作、「けす」を一段奥のテキストリンクに変更
  - ホーム声かけ文の複数予定時の扱い（最速1件を主役にし、他は「ほかにも用事がありますよ」の一言のみ）を明文化
  - E-1一覧の文字サイズを32px以上に引き上げ
  - 「0.2 改行・文字数制御方針」を新設（当初「1文=1行」だったが、実際の文言との不整合が発覚し「1文=最大2行」に改定）
  - C-2（聞き取れなかった状態）、E-1一覧、E-2詳細の文言・行分割を目安文字数に整合させる修正
  - 「7. 全画面文言の文字数適合チェック」の自己点検表を新設
  - 6章に最小端末（iPhone SE相当375×667pt）での高さ検証を追加
- 最終的にqa-accessibility・product-reviewer双方から「実装着手可」の判定を取得

## 3. visual-design：ビジュアル方針（複数回の追加対応）
成果物：`docs/concierge-visual-design.md`
- 配色：生成り紙色`#F6EFE4`・焦げ茶インク`#2B2420`・深松葉緑`#2F4A3E`（進める色）・煉瓦色`#7A3B2E`（削除のみ）の4色構成
- コントラスト比はqa-accessibilityの独立検算でも全組み合わせ7:1以上を確認
- ユーザーから共有された参考画像（紫系配色のアプリ）について検討し、**不採用と判断**（白背景・白カード構造がv1と本質的に同じ、ビビッドな紫は「高級ホテルのコンシェルジュ」文脈と相容れない、ピンク警告色は不安を煽らない方針と矛盾、パステル多色バッジは色数抑制の原則と衝突、という理由）。既存の温かい配色方針を維持。
- senior-uxの「0.2 改行・文字数制御方針」に対応するCSS方針（`word-break`, `overflow-wrap`, `text-overflow: ellipsis`等）を追記
- code-reviewでの指摘を受け、削除確認オーバーレイの「やめる」ボタンの配色矛盾（パネルとボタンが同色で視認不可）を検証し、新色を追加せず縁取り（`border: 1.5px solid rgba(43,36,32,0.35)`）で解決する方針を正式決定

## 7. qa-accessibilityブラウザ確認（2回、最終「合格」）
- 1回目：ホーム出発時刻文・E-1内容行の見切れ（390×844でも発生）、マイク案内文の孤立文字改行を発見 → 差し戻し

## 8. product-reviewerコンシェルジュらしさ評価（2回、最終「生活コンシェルジュとして成立」）

## 9. 残っている軽微な課題（ブロッカーではない、申し送り事項）
- C-2のフェイルセーフ発動時、助動詞の途中で改行される箇所がある（読解は可能、次回改版で文言データ側に明示的な改行位置を追加すると望ましい）
