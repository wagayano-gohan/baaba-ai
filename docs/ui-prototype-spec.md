- 作成者: UI/UX設計担当（senior-ux）
- 作成日: 2026-07-29
- 対象範囲: 画面構成・レイアウト・文言・配色・文字サイズ・タップ領域・画面遷移
- 対象外: 音声認識・AI応答生成・データ保存・認証・通信エラー処理・実装コード（これらは本仕様書の範囲外。実装はfrontend-web担当が別途行う）

## 0. このプロトタイプの目的と前提

本プロトタイプは、自立した高齢の祖母（利用者本人1名）が、音声AIコンシェルジュ「ばーばAI」を迷わず使えるかどうかを、**画面遷移と見た目・操作性のみ**で確認するための試作品である。

- 音声認識・AI応答・音声合成・データベースへの保存・ログイン認証は一切実装しない。
- 画面上のボタン操作によって、あらかじめ決められた画面へ遷移するだけでよい（すべてダミーデータ・ダミー遷移）。
- 「介護」「監視」「見守り」を想起させる表現・アイコン・配色は使用しない。利用者にとってはあくまで「話しかけると手伝ってくれる、感じの良い道具」であるという体験を優先する。
- PWA・API・DB・認証など開発者向けの専門用語は、画面上のテキストに一切表示しない（本仕様書内の技術メモを除く）。

## 1. デザイン原則（全画面共通）

1. **1画面1操作**: 各画面で利用者に求める主要な行動は必ず1つに絞る。選択肢を並べる場合も「はい／ちがう」のような二択までとする。
2. **大きく・太く・はっきり**: 文字は太字を基本とし、細字（Light/Thin）は禁止する。
3. **余白を惜しまない**: 要素同士の間隔を広くとり、詰め込まない。1画面に入れる情報は最小限にする。
4. **平易な日本語**: 漢字は日常的に使うものに限定し、難しい漢字にはふりがな相当の配慮（ひらがな表記への置き換え）を検討する。専門用語・カタカナ語（PWA、AI処理、データ、システム等）は画面上に出さない。
5. **一貫したフィードバック**: ボタンは押した瞬間に色が変化し、押されたことが視覚的にわかること（タップ時のハイライト状態を全ボタンに設定する）。
6. **落ち着いた清潔感**: Apple製品のような、白を基調にした静かな配色とし、原色・蛍光色・過度なグラデーションは使用しない。

## 2. 画面サイズ・基準デバイス

- 基準デバイス: iPhone縦画面
- 設計基準サイズ: 幅390px × 高さ844px（iPhone 13/14相当）
- 対応幅レンジ: 375px 〜 430px（iPhone SE 〜 iPhone Pro Max）
- 対応高さレンジ: 667px 〜 932px程度（iPhone SE第2/3世代の667px 〜 iPhone Pro Maxの932px程度までを想定）
- レイアウトは縦画面固定とし、横画面（回転）は対応不要
- セーフエリア（ノッチ・ホームインジケーター）を避け、上下に最低24pxの余白を確保する
- **低い高さの端末（667px前後）でのオーバーフロー時の方針**: 3章の文字サイズ・タップ領域・余白の最小値はどの端末高さでも縮小しない（フォントを小さくする、パディングを削るといった「圧縮」による対応は禁止）。画面内の全要素が667px高の画面に収まらない場合は、**画面全体の縦スクロールを許可する**ことで対応する。特に要素を上から積み上げる構成のホーム画面（7章）は、この方針の対象になりやすいため7.2でも改めて言及する。

## 3. タイポグラフィ・タップ領域ガイドライン（数値基準）

| 項目 | サイズ・数値 | 用途 |
|---|---|---|
| 最重要時刻（予定時刻など） | 36px以上（推奨40px） | 「10時30分」など、最も重要な時刻情報 |
| 画面の主見出し | 32px、太字（Bold） | 「この よていを 登録しますか？」等 |
| 本文文字 | 28px以上、太字寄り（Semibold以上） | 予定内容、案内文など通常テキスト |
| 補助ラベル文字 | 22px以上（本文より小さくしてよい最小値） | 「つぎの よてい」等のラベルのみ |
| 行間（line-height） | 文字サイズの1.6〜1.8倍 | 全テキスト共通 |
| フォント | 端末標準フォント（ヒラギノ角ゴ/システムフォント）を使用、Light・Thinウェイトは禁止 | 全画面共通 |
| ボタン・アイコンのタップ領域 | 最低88px × 88px | マイクボタン、停止ボタン、はい/ちがう、変更/削除、下部メニュー等すべて |
| 主要ボタン（マイク・はい・ちがう・停止） | 推奨120px × 120px以上（円形または角丸正方形） | 1画面の主操作となるボタン |
| タップ領域同士の間隔 | 最低16px、推奨24px以上 | 誤タップ防止のため隣接ボタンは必ず離す |
| 文字色とのコントラスト比 | 背景に対して**4.5:1以上を必須**とし、**7:1以上（WCAG AAAレベル相当）を可能な範囲で推奨**とする | 薄いグレー文字・低コントラストは禁止。実際の色の検証結果は4.3参照 |

補足: 文字サイズは「小さく作って後で拡大する」のではなく、上記を**最小値**として扱うこと。プロトタイプ段階で少しでも小さいと感じた場合は大きくする方向で調整してよい。コントラスト比についても同様に、4.5:1はあくまで下限であり、7:1に近づけられる箇所は積極的に濃色側へ調整すること（詳細な色の検証は4.3を参照）。

## 4. 配色案（カラーガイドライン）

Apple製品を思わせる、白を基調にした清潔で静かな配色とする。原色・ビビッドカラー・派手なグラデーションは使用しない。彩度を落とした落ち着いたトーンで統一する。

### 4.1 基本カラーパレット

| 役割 | 色名の方向性 | カラーコード目安 | 用途 |
|---|---|---|---|
| 背景色（基本） | 温かみのあるオフホワイト | `#FAF8F5` | 全画面の背景 |
| 背景色（カード・パネル） | 純白に近い白 | `#FFFFFF` | 予定カード、確認パネルなど |
| 文字色（基本） | ほぼ黒に近いダークグレー | `#2C2C2E` | 本文・見出し全般（純黒は使わずやや柔らかく） |
| 文字色（補助ラベル） | ダークミディアムグレー（可読性確保のため通常のミディアムグレーより濃色に調整） | `#595959` | 「つぎの よてい」等の小さめラベルのみ |
| メインアクセント（マイクボタン等） | 落ち着いたスレートブルー（濃色調整版） | `#2D5A78` | マイクボタン、下部メニューの選択中タブ、変更ボタンの枠線など |
| 肯定・「はい」ボタン | 深みのあるフォレストグリーン（セージグリーンより濃色に調整） | `#2E5A44` | AI確認画面の「はい」ボタン |
| 中立・「ちがう」ボタン | ライトグレー地に濃い文字 | 背景`#ECEAE5`／文字`#2C2C2E` | AI確認画面の「ちがう」ボタン（否定色＝赤は使わない） |
| 注意・削除ボタン | 深みのあるテラコッタ（バーントシエナ、赤みを抑えた暖色を濃色調整） | `#823C2D` | 予定一覧の「けす」ボタン（警告的だが刺激的すぎない色） |
| 録音中インジケーター | 深みのあるテラコッタ（削除ボタンと同色に統一） | `#823C2D` | 録音中画面の「聞いています」表示に添える点滅ドットのみ |
| 下部メニュー非選択タブ | ダークグレー（視認性確保のため濃色に調整） | `#6C6C6C` | 下部メニューの非選択タブの文字・アイコン |
| 罫線・区切り線 | ごく薄いグレー | `#E3E1DC` | カードの境界線、区切り線 |
| 影（シャドウ） | 黒の低透過度 | `rgba(0,0,0,0.06)` | カードの浮き上がり感（ごく控えめに） |

### 4.2 配色方針の補足

- 背景は純白ではなく、わずかに温かみのあるオフホワイト（`#FAF8F5`）にすることで、長時間見ても目が疲れにくく、かつ清潔感を保つ。
- ボタンの色は「意味」で統一する: 青系＝進める/話す、緑系＝肯定（はい）、グレー系＝中立（ちがう/戻る）、テラコッタ系＝削除（注意喚起だが赤そのものではない）。
- どの画面でも同時に使う強い色は最大2色まで（例: AI確認画面なら緑とグレーのみ）とし、視覚的な迷いを生まない。
- 角丸（border-radius）はボタン・カードともに20px前後に統一し、柔らかく親しみやすい印象にする。

### 4.3 コントラスト比の検証（アクセシビリティ根拠）

3章で定めたコントラスト基準（4.5:1以上を必須、7:1以上を可能な範囲で推奨）に対し、4.1のカラーパレット（v2・本改訂版）が実際に満たす値は以下のとおり。背景は白系（`#FFFFFF`/`#FAF8F5`、両者はほぼ同輝度のため同一視して計算）を基準とする。

| 前景色（文字・アイコン） | 背景色 | 用途 | 実測コントラスト比（目安） | 判定 |
|---|---|---|---|---|
| `#595959`（補助ラベル） | 白系背景 | 「つぎの よてい」等のラベル | 約7.0:1 | 7:1推奨を達成 |
| `#2D5A78`（メインアクセント） | 白系背景 | 選択中タブの文字・アイコン、変更ボタンの文字 | 約7.4:1 | 7:1推奨を達成 |
| 白文字 | `#2E5A44`（はいボタン） | 「はい」「へんこうする」ボタン文字 | 約7.9:1 | 7:1推奨を達成 |
| 白文字 | `#823C2D`（けすボタン） | 「けす」ボタン文字 | 約8.0:1 | 7:1推奨を達成 |
| `#6C6C6C`（非選択タブ） | 白系背景 | 下部メニュー非選択タブの文字・アイコン | 約5.3:1 | 必須基準（4.5:1）を上回る。非選択状態のため選択中タブより意図的にやや控えめだが、単独でも通常文字として十分読める水準を確保 |
| `#2C2C2E`（基本文字） | 白系背景 | 本文・見出し全般 | 約15:1超 | 余裕をもって達成 |

補足: 改訂前のパレット（メインアクセント`#3E6B8A`、はいボタン`#4F8F6D`、けすボタン`#B85C4F`、補助ラベル`#6E6E73`、非選択タブ`#8E8E93`）はいずれも4.1の値を下回っていたため、本改訂で上表の色に置き換えた（QAレビュー指摘反映）。今後、配色を変更する場合は必ず本節と同様の検証を行い、最低4.5:1・目標7:1を満たすことを確認してから採用すること。

## 5. 画面遷移図

```
                     [起動]
                        |
                        v
                +-------------------+
                |   ① ホーム画面     | <----------------------------+
                +-------------------+                              |
                 |マイクボタン tap    | 下部メニュー「よてい」tap      |
                 v                    v                             |
        +-------------------+   +-------------------+               |
        | ② 録音中画面        |   | ④ 予定一覧画面      |               |
        +-------------------+   +-------------------+               |
         |停止ボタン tap                | 「へんこう」tap  | 下部メニュー「ホーム」tap
         v                              v                  |
        +-------------------+    (③のレイアウトを流用      +----------> ①へ戻る
        | ③ AI確認画面        |     した編集用画面として表示)
        +-------------------+
         |「はい」tap → 短い完了表示(1.5秒) → ①へ自動遷移
         |「ちがう」tap → そのまま①へ遷移
         v
                ①ホーム画面へ戻る
```

### 5.1 遷移の詳細

| 起点画面 | 操作 | 遷移先 | 備考 |
|---|---|---|---|
| ①ホーム | 中央の大型マイクボタンをタップ | ②録音中画面 | 唯一の主要操作 |
| ①ホーム | 下部メニュー「よてい」をタップ | ④予定一覧画面 | |
| ②録音中 | 大型停止ボタンをタップ | ③AI確認画面 | 常時録音はしない。停止操作で次へ進む |
| ③AI確認 | 「はい」をタップ | 画面中央に「とうろくしました」を1.5秒表示 → ①ホームへ自動遷移 | 実際の登録処理は行わない（見た目のみ） |
| ③AI確認 | 「ちがう」をタップ | ①ホームへ即時遷移 | 確認メッセージなどは不要（誤操作時のやり直しは単純に戻るのみ） |
| ④予定一覧 | 下部メニュー「ホーム」をタップ | ①ホーム | |
| ④予定一覧 | 各カードの「へんこう」をタップ | ③AI確認画面のレイアウトを流用した編集表示（該当予定のデータを表示、ボタン文言のみ「はい」→「へんこうする」に差し替え） | 新規画面は作らず③のレイアウトを再利用する。ボタン文言は一覧画面の「へんこう」と語彙を統一する |
| ④予定一覧 | 各カードの「けす」をタップ | その場に確認ダイアログ「本当に けしますか？」を表示（「けす」/「やめる」の二択） | 誤操作防止のための確認のみ。通信・エラー処理は対象外 |

補足: 画面下部メニューは①ホームと④予定一覧の2画面間の切り替えにのみ関与する。②録音中・③AI確認は一連の操作フローの途中画面のため、下部メニューは表示しない（操作を1つに絞るため）。

## 6. 下部メニューの仕様（①・④共通）

- 画面最下部に固定表示するタブバー。高さ88px以上を確保する。
- タブは2つのみ: 「ホーム」「よてい」
- 表示形式: アイコン（家マーク／カレンダーマーク）＋ラベル文字（22px以上、太字）
- 選択中タブ: 文字・アイコンをメインアクセント色`#2D5A78`にする
- 非選択タブ: 文字・アイコンをグレー`#6C6C6C`にする
- タブ全体のタップ領域: 横幅を2分割し、それぞれ最低88px四方を確保
- 背景色: `#FFFFFF`、上部に薄い区切り線`#E3E1DC`を1本引く
- 録音中画面・AI確認画面には表示しない（1画面1操作の原則を優先し、離脱導線を減らす）

## 7. 画面①: ホーム画面

### 7.1 目的
起動時に最初に表示される画面。今日の状況を一目で把握し、話しかける（マイクボタンを押す）ことを促す。

### 7.2 レイアウト（上から下へ、優先順位順）

1. **上部エリア（日付・挨拶）**
   - 今日の日付: 「7月29日（水）」形式、28px以上、`#2C2C2E`
   - 挨拶文（時間帯に応じて自動切替。本文4.文言例を参照）: 32px、太字
   - 上下左右の余白: 24px以上
2. **中央エリア（次の予定カード）**
   - 白背景のカード（角丸20px、薄い影）
   - ラベル「つぎの よてい」: 22px、`#595959`
   - 予定時刻: 36px以上、太字、`#2C2C2E`（画面内で最も目立つ数字）
   - 予定名: 28px、`#2C2C2E`
   - その下に「でかける時間」ラベル（22px）＋出発時刻（28px以上、太字）
   - カード内の要素間の余白: 12〜16px
   - カードの外側パディング（カード枠から内側の各要素までの距離）: 上下左右24px程度（10.2の予定一覧カードと同一の考え方で統一する）
3. **下部エリア（マイクボタン）**
   - 画面中央下寄りに配置する大型円形ボタン、直径140px以上
   - 背景色`#2D5A78`、内側にマイクのアイコン（白）
   - ボタン直下に短い案内文「ボタンを おすと おはなしできます」（22〜24px、`#595959`）
   - ボタン周囲の余白: 上下左右32px以上、他要素と重ならないようにする
4. **最下部: 下部メニュー**（5章・6章参照）

補足（端末高さ対応）: 上記1〜4の要素を667px程度の低い高さの端末で積み上げると収まらない場合がある。その際は文字サイズ・余白・タップ領域を縮小せず、画面全体の縦スクロールを許可すること（2章の対応高さレンジの方針に従う）。下部メニュー（4）は画面下部に固定し、スクロールしても常に表示されるようにする。

### 7.3 画面文言（確定文）

- 挨拶文（時間帯で切替。祖母の呼び名部分はダミーで「花子さん」とする）
  - 5:00〜10:59: 「おはようございます、花子さん」
  - 11:00〜16:59: 「こんにちは、花子さん」
  - 17:00〜翌4:59: 「こんばんは、花子さん」
- 日付表示: 「7月29日（水）」（曜日は括弧書き、和暦は使わない）
- 次の予定ラベル: 「つぎの よてい」
- 予定なしの場合の表示: 「きょうの よていは ありません」（28px、予定カード内に表示。今回のプロトタイプでは常に予定ありのダミーデータを表示すればよいため、参考表示のみ）
- 出発時刻ラベル: 「でかける時間」
- マイクボタン案内文: 「ボタンを おすと おはなしできます」
- 下部メニュー: 「ホーム」／「よてい」

## 8. 画面②: 録音中画面

### 8.1 目的
マイクボタンを押した直後に表示する、「今まさに話を聞いている」ことを一目で伝えるための画面。常時録音は行わず、この画面はボタン操作によって遷移してきたときにのみ表示する（本物の音声取得処理は実装しない）。

### 8.2 レイアウト

1. **中央上寄り: メインメッセージ**
   - 「聞いています」を画面中央よりやや上に大きく表示: 36px以上、太字、`#2C2C2E`
2. **メインメッセージ直下: 録音中インジケーター**
   - 赤系（`#823C2D`）の丸いドットが緩やかに点滅するアニメーション（1秒周期程度の穏やかな明滅）
   - ドット横に短い補助文言「おはなし ください」（24px、`#595959`）
   - 派手なアニメーション（波形が激しく動く等）は避け、ゆったりとした呼吸のような動きにする
3. **画面中央: 大型停止ボタン**
   - 直径140px以上の円形ボタン、背景色`#2D5A78`
   - ボタン中央に四角い停止アイコン（白）
   - ボタン直下に案内文「おわったら ボタンを おしてください」（24px）
   - 画面内で唯一のタップ可能要素とする（誤操作防止のため、他のボタン・メニューは一切表示しない）
4. 下部メニューは非表示（この画面は一連の操作の途中であるため）

### 8.3 画面文言（確定文）

## 9. 画面③: AI確認画面

### 9.1 目的
録音停止後に、聞き取った（という体で用意された）予定内容を利用者に見せ、正しいかどうかを確認してもらう画面。

### 9.2 レイアウト

1. **上部: 見出し**
   - 「この よていを 登録しますか？」32px、太字、`#2C2C2E`、中央揃え
   - 上部余白32px以上
2. **中央: 内容確認カード**
   - 白背景カード（角丸20px、影あり）
   - 日付: 28px以上、`#2C2C2E`（例: 「7月30日（木）」）
   - 時刻: 36px以上、太字、`#2C2C2E`（画面内で最も目立つ数字。例: 「10時30分」）
   - 予定内容: 28px以上、`#2C2C2E`（例: 「病院（内科）」）
   - 各項目間の余白: 16px以上、ラベルは付けずシンプルに数字と文言のみを大きく見せる
3. **下部: 二択ボタン（左右または上下に並べる。上下配置を推奨）**
   - 「はい」ボタン: 幅いっぱい〜160px以上、高さ88px以上、背景`#2E5A44`、白文字28px以上太字
   - 「ちがう」ボタン: 同サイズ、背景`#ECEAE5`、文字`#2C2C2E`
   - 2つのボタンの間隔: 24px以上
   - 「はい」を上（先）に、「ちがう」を下に配置し、推奨操作をわずかに強調する
4. 下部メニューは非表示

### 9.3 画面文言（確定文）

- 見出し: 「この よていを 登録しますか？」
- ボタン: 「はい」／「ちがう」
- 「はい」タップ後の完了表示（新規画面ではなく、画面中央にオーバーレイで1.5秒表示してからホームへ自動遷移）: 「とうろくしました」（32px、太字、背景は半透明の白でよい）

## 10. 画面④: 予定一覧画面

### 10.1 目的
今日以降に登録されている（という体の）予定を、大きなカードの一覧として見せる画面。変更・削除の操作口を用意する。

### 10.2 レイアウト

1. **上部: 見出し**
   - 「よてい」28px以上、太字、左上または中央に配置
   - 上部余白24px以上
2. **中央: 予定カードの縦並びリスト（スクロール可）**
   - 1件＝1カード、白背景・角丸20px・影あり
   - カード内構成（上から）:
     - 日付（例: 「7月29日（水）」）: 24px以上、`#595959`
     - 時刻（例: 「10時30分」）: 36px以上、太字、`#2C2C2E`
     - 予定内容（例: 「病院（内科）」）: 28px以上、`#2C2C2E`
     - ボタン行: 「へんこう」（幅48%程度、高さ88px以上、`#2D5A78`のアウトラインボタン）と「けす」（幅48%程度、高さ88px以上、背景`#823C2D`、白文字）を横並びに配置、間隔16px以上
   - カード同士の間隔: 24px以上（誤って隣のカードのボタンを押さないよう十分に離す）
   - カード内側の余白（パディング）: 上下左右24px程度
3. 最下部: 下部メニュー（5章・6章参照）

### 10.3 画面文言（確定文）

- 見出し: 「よてい」
- ボタン: 「へんこう」／「けす」
- 削除時の確認ダイアログ見出し: 「本当に けしますか？」
- 削除確認ダイアログのボタン: 「けす」（`#823C2D`）／「やめる」（`#ECEAE5`、`#2C2C2E`文字）
- 予定が1件もない場合の表示（参考。プロトタイプでは常時ダミーデータを表示すればよい）: 「よていは ありません」

### 10.4 「へんこう」タップ時の挙動
新規画面は作らず、③AI確認画面のレイアウトを再利用して表示する。差分は以下のみ。

- 見出しを「この よていを 登録しますか？」→「よていを 変更しますか？」に差し替え
- ボタン文言を「はい」→「へんこうする」に差し替え（色は同じ`#2E5A44`）、「ちがう」→「やめる」に差し替え（色は同じ`#ECEAE5`）
  - 「へんこうする」は予定一覧画面（10.3）の「へんこう」ボタンと同じ語彙で統一し、「変更する行為＝へんこう」という言葉を画面をまたいで一貫させる
- 「へんこうする」タップ後は「へんこうしました」を1.5秒表示 → ④予定一覧へ自動遷移
- 「やめる」タップ後は即座に④予定一覧へ遷移

## 12. 使用してはいけない表現・注意事項（全画面共通チェックリスト）

- 「介護」「監視」「見守り」という単語、およびそれらを連想させるアイコン（カメラ、GPS、通知アラート的な赤いバッジ等）は使用しない。
- 「PWA」「API」「AI処理」「データベース」「エラー」「通信」等、開発者向け・技術的な単語は画面上に一切表示しない。
- カタカナ語は最小限にする（「デイサービス」等、利用者本人が日常的に使っている言葉は許容する）。
- 細字（Light/Thin）フォント、薄いグレー文字（コントラスト比4.5:1未満。7:1に達しない場合も理由なく妥協しない）、小さすぎるタップ領域（88px未満）は使用しない。
- 蛍光色・原色・強いグラデーションは使用しない（4章のカラーパレットのみを使用する）。
- 1画面に複数の主要操作ボタンを並べない（②③は各1操作、④は各カード内の2ボタンのみ許容）。
