## 本書について

本書は、product-requirements（新要件定義）／senior-ux（画面構成設計）／visual-design（ビジュアル方針）／qa-accessibility（アクセシビリティ・実機確認）／frontend-web（実装）／code-reviewer（コードレビュー）／product-reviewer（コンシェルジュらしさ評価）の各専門サブエージェントによる、複数回のレビュー・差し戻しサイクルを経て完成した「コンシェルジュUI（v2）」の完了報告です。

v1（不採用）は、日付＋挨拶＋予定カード（各カードに「へんこう」「けす」ボタン常設）＋マイクボタン＋常設ボトムタブバーという構成で、社内レビューの結果「予定管理アプリに見える」「操作・情報が多く考えさせる」という理由で不採用となりました。v2は、これを「会話文＋大型音声ボタンを主役とし、カード・タブバー・常設の複数ボタンを廃した」構成へ全面刷新したものです。詳細な不採用理由・原則は`docs/concierge-requirements.md`を参照してください。

## 2. 新しい画面一覧

5画面（内部的にはC・Eがそれぞれ2状態を持つため計7状態）で構成。

| 画面 | 名称 | 内容概要 |
|---|---|---|
| A | コンシェルジュホーム | 挨拶＋予定・出発時刻・天気を溶け込ませた声かけ文（一続きの文章、カード化しない）と、画面主役の大型音声ボタンのみ。最下部に控えめなテキストリンク「予定をみる」1本。 |
| B | 聞き取り中 | 「聞いています」の大表示、穏やかな録音インジケーター、大型停止ボタンのみ（唯一の操作）。 |
| C-1 | AI確認（内容を確認する状態） | AIが理解した内容を日付・時刻・内容の一続きの確認文として表示し、「はい」「ちがう」の二択のみ。 |
| C-2 | AI確認（聞き取れなかった状態） | 責めない優しいお詫び文言のみ。ボタンなし、2.5秒で自動的にBへ遷移。 |
| D | 完了 | 「登録しました／変更しました／削除しました」のいずれかの一言＋安心を添える補助文言。画面全体がタップ領域で早送り可能、2.5秒で自動遷移。 |
| E-1 | 予定一覧 | 見出し「予定」＋日付順の行リスト（1行＝日付・時刻／内容の2行構成、ボタンなし）＋「＜ もどる」。カレンダーグリッドは使わない。 |
| E-2 | 予定詳細 | 選んだ1件を日付・時刻・内容の一続きの文章で表示。常設の主操作は「変更する」1つのみ。削除は一段奥のテキストリンク「この予定を削除する」から、その場のオーバーレイ（「けす」／「やめる」）で確認する。 |

## 3. 画面遷移

```
A（ホーム）
 ├─ マイクボタンタップ ────────────▶ B（聞き取り中）
 │                                       │ 停止ボタンタップ
 │                                       ▼
 │                                  C（AI確認）
 │                                  ├─ 内容を理解できた場合＝C-1
 │                                  │   ├─「はい」──▶ D（登録/変更しました）─ 自動2.5秒 or 任意タップ ─▶ 遷移元に応じてA or E-1
 │                                  │   └─「ちがう」─▶ 一言表示 ─▶ B（再度聞き取り）
 │                                  └─ 聞き取れなかった場合＝C-2
 │                                      └─ お詫び表示（自動2.5秒）──▶ B（再度聞き取り）
 │
 └─ 画面下部「予定をみる」タップ ───▶ E-1（予定一覧）
                                          │ 行タップ
                                          ▼
                                     E-2（予定詳細、主操作は「変更する」のみ）
                                     ├─「変更する」──▶ B ▶ C-1(変更用文言) ▶ D(変更しました) ▶ E-1
                                     ├─（一段奥のテキストリンク）「この予定を削除する」
                                     │      ──▶ 削除確認オーバーレイ（その場表示）
                                     │            ├─「けす」──▶ D(削除しました) ▶ E-1
                                     │            └─「やめる」──▶ E-2に戻る
                                     └─「＜ もどる」──▶ E-1
E-1「＜ もどる」──▶ A
```

要点:
- 常設のボトムタブバー（アイコン＋ラベル固定メニュー）は作らない。A・E間の行き来はテキストリンク「予定をみる」／「＜ もどる」のみ。
- Dは新規登録・変更・削除の3用途で共通利用し、遷移元がAなら戻り先はA、遷移元がEなら戻り先はE-1。
- E-2の同時常設操作は「変更する」1つのみで、削除は誤タップ防止のため一段奥に配置。

## 7. qa-accessibilityの結果

2回のレビューサイクルを経て、最終判定は**「合格」**。

- **1回目（差し戻し）**：390×844の実機相当サイズでも発生する以下を指摘。
  - ホーム画面の出発時刻文の文字見切れ
  - E-1一覧の内容行の文字見切れ
  - マイク案内文（B画面）の孤立文字改行（不自然な位置での折り返し）
- **2回目（合格）**：上記4件の解消を、scrollWidth/clientWidthの機械的検証によって実測で確認。
- **残っている軽微な課題（ブロッカーではない、申し送り事項）**：E-1一覧の内容省略が、`concierge-screen-design.md`記載の「12文字＋…」より短く（約8文字＋…）表示される。`.text-line--variable`のmax-width:280pxがやや保守的すぎることが原因。情報はE-2で全文参照可能なため実害はなく、正常なフェイルセーフ動作と判定。次回改版でmax-widthを300px前後へ調整することが推奨されている。

## 8. product-reviewerの評価

2回のレビューサイクルを経て、最終判定は**「予定管理アプリではなく、生活コンシェルジュとして成立」**。

- **1回目（差し戻し）**：文字見切れ（詫び画面C-2を含む）、および複数予定ロジックの未実装（設計上は解消済みだったが、コードに未反映）を発見。
- **2回目（最終判定）**：両修正を実機確認のうえ再評価し、要件定義の10原則、特に**原則5（考えさせない）**と**原則8（画面の主要操作は常に1つ）**への影響を重点的に検証。

10原則それぞれについての評価概要（`concierge-screen-design.md`・`concierge-ui-process-log.md`の記録に基づく）：
- **音声主役**：ホームの主役はマイクボタンであり、テキスト入力・カード選択等の代替導線を持たない構成を維持。
- **ホームは最小要素**：声かけ文（一続きの文章）＋マイクボタンの実質2要素構成に削減済み（v1の5ブロック構成から刷新）。
- **カード・箱型構造の不使用**：A〜Eすべてで枠・影付きカードを廃し、会話文・単一行動・最小限のリストのみで構成。
- **常設ボトムタブバーの廃止**：v1最大の失敗点であった常設タブバーを全廃し、A・E間はテキストリンクのみで接続。
- **考えさせない（原則4/5）**：C-2（聞き取れなかった場合）はボタンを置かず自動遷移のみで完結、D画面も自動遷移＋全画面タップの単純構成。
- **画面の主要操作は常に1つ（原則7/8）**：E-2の「変更する」「けす」同格ボタン問題は、変更のみを常設操作とし削除を一段奥のテキストリンクへ移す方針転換で解消。
- **文字サイズ・可読性**：主内容32px以上・最重要情報40px以上の基準を全画面に適用。
- **改行・省略の制御**：文言データ側で改行位置を明示的に確定し、CSSの自動ラップに委ねない方針で実装。
- **複数予定時の情報過多防止**：最速1件のみを主役にし、他は「ほかにも用事がありますよ」の一言に留める排他ロジックを実装（`src/utils/homeContent.ts`）。
- **責めない言葉づかい**：C-2のお詫び文言等、利用者を責めない優しい言い回しを一貫して採用。

## 9. 残っている問題（ブロッカーではない、軽微な申し送り事項）

1. **C-2の改行位置**：フェイルセーフ発動時、助動詞の途中で改行される箇所がある。読解は可能だが、次回改版で文言データ側に明示的な改行位置を追加することが望ましい。
2. **E-1の省略表示の保守性**：一覧の内容省略が設計書記載の「12文字＋…」より短く（約8文字＋…）表示される。`.text-line--variable`のmax-width:280pxがやや保守的すぎるのが原因。情報はE-2で全文参照可能なため実害はないが、次回`max-width`を300px前後へ調整することを推奨（7章のqa-accessibility結果と同一事項）。

いずれも実装差し戻しの対象にはならず、次回改版時の申し送り事項として記録されている。
